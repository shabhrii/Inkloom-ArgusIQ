# Phase tracker

Update this file during development. Do not mark a feature complete based only on generated code.

## Phase (1) — official requirements
- [ ] App boots locally
- [ ] Authentication and server-side roles
- [ ] Approved guidelines/facts/terminology/disclosures can be managed
- [ ] Supported upload and safe text extraction
- [ ] Deterministic rule checks
- [ ] Approved-source claim verification with insufficient-evidence state
- [ ] Structured findings with location and explanation
- [ ] Minimal correction preview without overwriting original
- [ ] Human review action and approval state
- [ ] Comments and revision history
- [ ] Basic recurring-issue summary
- [ ] Privacy disclosures and protected file handling
- [ ] Tests, demo fixtures and documentation
- [ ] Full end-to-end demo passes

## Phase (2) — add one at a time
- [ ] Visual asset matching and geometry checks
- [ ] Risk-adaptive review routing
- [ ] Stronger provenance/audit/versioning
- [ ] Evaluation corpus and metrics
- [ ] Vector/hybrid retrieval if justified
- [ ] CI workflows

After each checked item, run all tests and repeat the demo workflow before proceeding.

## Phase (3) — optional advanced enhancements
- [ ] Policy compiler with human validation
- [ ] Confidence calibration
- [ ] Active learning
- [ ] Advanced video/multimodal analysis
- [ ] Reranking and expanded deployment options
- [ ] Advanced policy coverage analytics

## Status vocabulary
- `implemented`: code exists and tests plus manual acceptance check pass.
- `partially implemented`: some supported cases work; limitations are documented.
- `planned`: not implemented.
